## Session

| Method | Returns | |
| --- | --- | --- |
| `init(config)` | `TrackResponse \| null` | Start a session and send the automatic signals once |
| `getSession()` | `SessionResponse` | Current session and inferred personas |
| `getSessionId()` | `string` | The current session id |
| `resetSession()` | `void` | Clear it and start fresh |
| `onPersona(cb)` | `void` | Subscribe to persona updates |

## Signals and ranking

| Method | Returns | |
| --- | --- | --- |
| `track(signals)` | `TrackResponse` | Send shopper signals |
| `search(products, options?)` | `SearchResponse` | Rank products you pass in |
| `rankedCatalog(options?)` | `RankedCatalogResponse` | Rank the catalogue already synced to PULSE |
| `event(type, data?)` | `EventResponse` | Record a named event |

<Callout>
  `search` and `rankedCatalog` are not interchangeable. `search` ranks what you hand it;
  `rankedCatalog` ranks what PULSE already holds.
</Callout>

## Beyond the client

`PulseClient` is most of the package and not all of it. These are exported too, for the cases
where you need a signal without a client, or need to look at what the SDK cached.

### Signal capture

`init()` calls `captureAutoSignals()` for you when `autoTrack` is on, so you only need these
directly when you want a signal at a different moment, or want one the automatic set leaves out.

| Export | Returns | |
| --- | --- | --- |
| `captureAutoSignals()` | `Signal[]` | Device, referrer and time in one call. What `init()` sends |
| `captureDeviceSignal()` | `Signal \| null` | Device class from the user agent |
| `captureReferrerSignal()` | `Signal \| null` | Where the visit came from |
| `captureTimeSignal()` | `Signal` | Time of day. Never null, there is always a clock |
| `captureEnhancedReferrerSignals()` | `Signal[]` | Campaign and channel detail beyond the plain referrer |
| `captureDeviceInfoAsync(): Promise` | `DeviceInfo` | Fuller device detail, including client hints |
| `captureGeoInfo(): Promise` | `null` | **Deprecated.** Always `null`: the Pulse API reads location from the request |
| `geoToSignals(geo)` | `Signal[]` | Turn a `GeoInfo` into signals |
| `captureWeatherInfo(lat, lon, apiKey?): Promise` | `WeatherInfo \| null` | **Deprecated.** The Pulse API adds weather itself |
| `weatherToSignals(weather)` | `Signal[]` | Turn a `WeatherInfo` into signals |
| `captureCulturalCalendar(countryCode)` | `Signal[]` | Seasonal and cultural events active today |
| `parseUserAgent(ua)` | `DeviceInfo` | Parse a user agent string you already have |

<Callout title="Location and weather need nothing from you">
  The Pulse API works out the visitor's country and city from the request and adds the weather
  there from its own cached reading, one lookup per city per hour. No key goes in the browser and
  no call leaves the page. A MAC address is never available to any website, so nothing reads one.
</Callout>

<Callout>
  `captureAutoSignals()` is exported for one specific failure. `init()` sends the automatic
  signals exactly once and swallows its own error, so a session whose `init()` failed never
  re-sends them and stays thin for its whole life. These signals cost no network of their own, so
  calling this again on a later page load is cheaper than the alternative.
</Callout>

### Session context

Device, location and weather are properties of the session rather than of the page: they cannot
change between one page and the next. The SDK captures them once, keys the cache by session id so
it cannot outlive the visitor it describes, and reuses it. You rarely need to touch this.

| Export | Returns | |
| --- | --- | --- |
| `readSessionContext(sessionId)` | `SessionContext \| null` | The cache, or null if it belongs to another session |
| `writeSessionContext(sessionId, patch)` | `void` | Merge fields into it |
| `isWeatherFresh(ctx, now?)` | `boolean` | Whether the weather reading is still inside its TTL |
| `clearSessionContext()` | `void` | Drop the cache |
| `WEATHER_TTL_MS` | `number` | 10 minutes |

<Callout>
  Weather is the only field here with a TTL. Everything else is immutable for the session, but a
  30-minute session can outlast a rain shower, and a `weather:rain` signal driving a
  recommendation after the sun came out is the engine being confidently wrong.
</Callout>
